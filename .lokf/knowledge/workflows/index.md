# Workflows

* [Build and test (main.yaml)](main.md) - The Build and test workflow, `.github/workflows/main.yaml`: on a push to main and on every pull request, its test job runs `just test` on Python 3.10 to 3.14, and on 3.13 also `just lint` and `just lokf-adapt-check`.
* [Lint & docs (lint-and-docs.yaml)](lint-and-docs.md) - The Lint & docs workflow, `.github/workflows/lint-and-docs.yaml`: on a push to main, every pull request, Mondays at 06:00 UTC and by hand, it runs ShellCheck, actionlint, the word budgets of CONTRIBUTING.md and SECURITY.md, markdownlint, lychee and codespell.
* [Upstream watch (upstream-watch.yaml)](upstream-watch.md) - The Upstream watch workflow, `.github/workflows/upstream-watch.yaml`: every Monday at 07:00 UTC and by hand, its co-copy job runs `scripts/check_upstream_release.py` against CO's GitHub repository, and on a finding opens or updates the issue titled Upstream watch: the Collections Ontology has changed.
* [Semantic release (semantic-release.yml)](semantic-release.md) - The Semantic release workflow, `.github/workflows/semantic-release.yml`: on a pull request its plan job says what a merge would release, and on a push to main its release job, in the release Environment, tags the release and dispatches Knowledge Release.
* [Knowledge website (knowledge-website.yaml)](knowledge-website.md) - The Knowledge website workflow, `.github/workflows/knowledge-website.yaml`: it builds the site on pull requests and pushes that touch its inputs, Mondays at 05:23 UTC and by hand, and deploys it to GitHub Pages once `KNOWLEDGE_WEBSITE_ENABLED` is `true`.
* [Knowledge Registrar (knowledge-registrar.yaml)](knowledge-registrar.md) - The Knowledge Registrar workflow, `.github/workflows/knowledge-registrar.yaml`: the bundle's gate, which validates `.lokf/` on pull requests, Mondays at 06:00 UTC and by hand, and checks that each new confirmation is backed by its person's approval or signed commit.
* [Knowledge Librarian (knowledge-librarian.yaml)](knowledge-librarian.md) - The Knowledge Librarian workflow, `.github/workflows/knowledge-librarian.yaml`: Mondays at 05:00 UTC and by hand, once `KNOWLEDGE_LIBRARIAN_ENABLED` is `true`, it runs the ktl-librarian skill pinned to KTL v0.59.0 in a job with no write token and opens a pull request with what changed.
* [Knowledge Release (knowledge-release.yaml)](knowledge-release.md) - The Knowledge Release workflow, `.github/workflows/knowledge-release.yaml`: on a published release once `KNOWLEDGE_RELEASE_ENABLED` is `true`, or by hand for a tag, it attaches the schema copy, the bundle zip and the Copilot skill zip, each with its checksum and attestation.
* [Knowledge sync (knowledge-sync.yaml)](knowledge-sync.md) - The Knowledge sync workflow, `.github/workflows/knowledge-sync.yaml`: Mondays at 04:10 UTC and by hand, it compares the sidecar's copies and the skills pin with the newest KTL release and opens one pull request when they are behind.
